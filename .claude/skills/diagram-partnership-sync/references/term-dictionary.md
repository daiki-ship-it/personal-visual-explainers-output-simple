# 用語辞書（AI講師 ⇄ SNSマーケ）

会議サマリーをSlackで共有するとき、**一方にとっては日常語・他方にとっては専門語**になりやすい。初出または重要箇所で必ず橋渡しする。

## 目次

- 変換の原則
- マーケ側が読むとき（AI・プロダクト用語 → やさしい言い換え）
- AI側が読むとき（SNS・マーケ用語 → やさしい言い換え）
- 用語ボックスの書き方

---

## 変換の原則

1. **役割で言い換える**: 「何をするための言葉か」を先に書く（手段の名前は後ろ）
2. **括弧は1行以内**: 長い定義はカードやボックスに逃がす
3. **略語は初出で展開**: 2回目以降だけ略語可
4. **社内固有名詞はそのまま**: ただし初出で一行説明を付ける

---

## マーケ側が読むとき（AI・プロダクト用語）

| 用語の例 | やさしい言い換え・一言 |
|---------|------------------------|
| プロンプト | AIへの依頼文・指示のまとまり |
| コンテキスト | AIが参照している前提情報・これまでの会話 |
| RAG | 社内資料などを検索してから答えを作る仕組み（検索＋生成） |
| ファインチューニング | 特定データでAIの出方を調整すること |
| API | システム同士が決まった手順でやり取りする窓口 |
| トークン | AIが処理する文章のかたまり（長さの目安） |
| ハルシネーション | もっともらしいが事実でない出力 |
| エージェント | 目的に向かって自律的に手順を進めるAIの動き方 |

※ トピックに応じて行を追加する。一覧は**例示**であり、会議内容のSSoTではない。

---

## AI側が読むとき（SNS・マーケ用語）

| 用語の例 | やさしい言い換え・一言 |
|---------|------------------------|
| リーチ | 投稿や広告が「何アカウントに表示されたか」の規模感 |
| インプレッション | 画面に表示された回数（同じ人に複数回あれば増える） |
| エンゲージメント | いいね・保存・コメント・シェアなどの反応の総称 |
| CTA | 読者に取ってほしい次の行動（リンククリック・登録など） |
| コンバージョン | 設計した「成果」（申込・資料請求など）に至った数 |
| ペルソナ | 想定している典型ユーザー像 |
| オーガニック | 広告費を使わずに届いた流入・反応 |
| UGC | ユーザーが作った投稿・レビューなどの素材 |

※ 同上、**例示**。

## 用語ボックスの書き方

`creating-visual-explainers` のコンテンツ領域内で、Tailwindのみでカードを作る。色は `ads-*` パレットに合わせる。

**構成の型**:

- 小見出し: 「〇〇とは（マーケ担当向け）」「〇〇とは（AI担当向け）」のように**誰のための補足か**を明示
- 本文: 1〜3文＋必要なら「この会議では△△の意味で使う」と固定

図解テンプレートの枠組み・クラス詳細 → 親スキルの `base.html` / `model-answer.html` を参照すること。
